# todo-loop の積み足し — 無人セッションへの指示書

あなたは無人で起動された。user はこの実行を見ていない。質問せず、最後まで自分で進める。

## やること
1. `{{PROJECT}}/CLAUDE.md` があれば Read で最後まで読む。`{{PROJECT}}/TODO.md` の運用節を読む。
2. 材料台帳を読む: {{LEDGER}}
   台帳の未処理の材料は、観点と合わせて「何を積むか」を決める入力にする（観点が出す施策と同じ型の材料があれば、その施策の根拠にする）。
3. `Skill` ツールで `lens-next` を起動する。引数: `{{PROJECT}} {{LENS}} 10`
   - skill の「既出」には、`{{PROJECT}}/TODO.md` の全ストーリー（done を含む）を含めて除く。
4. 出した 10 件のうち、**優先度の上位 3 件**を選ぶ。ただし、user の操作・判断・好みの選択が要るもの、外部への公開が本体のものは選ばない（TODO.md の運用節に「積まない物」があればそれも除く）。
5. その 3 件を skill の手順 7 に従って `{{PROJECT}}/TODO.md` に積む。
   - **完了まで 1 SP ずつに分解する**（1 SP = 運用節の定義。無ければ「触るファイル 1〜2、検証 1 コマンド、目安 45 分以内」）。
   - **ファイルの末尾にだけ追記する。** 既存の行は 1 文字も変えない（runner が検査し、崩れていたら実行前に戻す）。
   - 末尾に節 `## lens-next（YYYY-MM-DD HH:MM、S-NN〜）` を作り、冒頭に「施策 → ストーリー番号の対応」を書く。
   - 番号は積む直前に TODO.md の使用中の最大値を読み、その続きから取る（無ければ S-01）。状態はすべて `todo`（下の「ランナー自身の直し」だけ例外）。モデル列は調査 = `fable`、実装 = `opus`。
   - 見出しは `## S-NN — <項目> | <調査|実装> | <fable|opus> | todo`。本文に `- 範囲:` / `- 完了条件:`（検証コマンド 1 つで判定できる形）/ `- 依存:`（無ければ「なし」）/ `- 外部作用:`（無ければ「なし」）/ `- 証跡:` / `- 引き継ぎ:`。
   - 台帳の材料に拠ったストーリーは、`- 範囲:` に**そのストーリーが扱う材料の番号だけ**を書く（話の違う番号を添えない）。範囲 に書いた番号は次の回で台帳から外れる。
6. **ランナー自身の直し**: 台帳の材料（中断の繰り返し・blocked 化・積み足しの失敗など）が、このランナーの設定・足し書き（`{{STATE}}` の lens・passes・story-addon.md・refill-addon.md）・プロジェクトの道具の直しで防げるなら、その直しの提案を上の 3 件とは別に 1 件まで積んでよい。
   - 状態は `awaiting-approval` で積む（user が読んで `approved` に書き換えた回だけ、次のセッションが直しを当てる）。
   - `- 外部作用:` 欄に、当てる差分（ファイルのパスと、変える前後の行。unified diff の形でよい）をそのまま書く。
   - 直す先が todo-loop の本体（`plugins/todo-loop/` の runner・指示書・道具）なら、外部作用 欄の先頭に「本体（plugins/todo-loop）への直し: どの環境にも効く」と明記する。本体の直しにプロジェクト固有の名前・パスを入れない。
7. 報告を書く: 上の「報告の置き場」のディレクトリに、上の「報告のファイル名」で JSON を Write で書き、`python3 {{REPORT_PY}} check <その json の絶対パス>` が `OK` を返すまで直す。
   積んだ施策を 1 要素ずつ。各要素は `{"施策", "ストーリー"（積んだ ID の配列）, "課題", "やったこと"（この回に調べた実測）, "まとめ", "つまづいたこと"（無ければ「無し」）, "工夫したところ", "何が嬉しいのか", "発展可能性", "完了したかどうか"（積んだ（未着手）／awaiting-approval・blocked で積んだ物の有無）}`。値は文字列か文字列の配列。
   user はこの報告を読んで内容を精査し、次を考える。確かめられなかったことを正直に書く。

## やらないこと
- ストーリーを実行しない（積むだけ）。コード・道具・設定を変えない（直しは 6. の提案として積むだけ）。
- `git commit`・`git push`・公開・常駐登録の操作をしない。
- TODO.md の既存部分（運用節・既存ストーリー）を編集しない。

## 最後の出力
最終メッセージの末尾に、次の形を**そのまま**出す:

```
LENS-SUMMARY
- 選んだ 3 件: <題 1> / <題 2> / <題 3>
- 積んだ番号: S-NN〜S-MM（<件数> 件）
```
