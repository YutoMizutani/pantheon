# 観点: 信頼できる情報源を増やし、1 本の情報源への依存を減らす

この観点は、TODO の探索の向きを「プロジェクトの中を良くする」から「プロジェクトが外から何を取り込んでいるか」へ広げるためのもの。
ほかの観点（改善・野心など）とは別の回で回し、そちらが出す施策は再掲しない。

## 何を良くしたいか
- プロジェクトの判断・成果物が、どの外部の情報源（サイト・API・データ・論文・作者・コミュニティ）に支えられているかを実測し、
  **1 本の情報源だけで決めている判断**を見つけて、性質の違う 2 本目（一次・作者の解説・集計・実測の記録）を足す。
- 情報源ごとに「何が分かるか／何が分からないか」を書き分ける。集計（何人がどう使っているか）・作者の解説（なぜ・どの順で・予算ごと）・
  一次（公式・データ・原典）・実測（自分や user の記録）は代わりにならない。足りない種類を探す。
- 足した情報源は、読み物で終わらせず、**道具が機械で取れる形**にする（取得口・認証の要否・弾かれ方と通る名乗り・更新日の取り方を確かめ、
  取得の道具か手順を作る）。人が毎回手で開く経路は、拡充に数えない。

## 精査の問い（材料が無くても回せる）
1. 直近の成果物・判断（TODO の done・ログ・報告）が引いた情報源を数える。1 種類に偏っている判断の型はどれか。
2. その型の判断について、同じ分野の上級者・専門家が見る情報源は何か。まだ使っていない物を、実際に取得して確かめる
   （名前を挙げるだけで終えない。取得結果・最終更新日・版の表記・本文が機械で取れるかを証跡に書く）。
3. 足す候補の信頼の根拠は何か: 一次ソースか、作者が名乗っているか、版と更新日が書かれているか、ほかの情報源と照合して食い違いが無いか。
   根拠を書けない候補は積まない。
4. 今使っている情報源が古くなった・取れなくなった・別の情報源と食い違うものは無いか。食い違いの記録と、どちらを正とするかの決まりを作る。
5. 情報源の一覧（どこに何を取りに行くか）がプロジェクトのどこにあるか。無い・散らばっているなら、1 か所の索引にまとめる施策を出す。

## 積み方の決まり
- 施策は「この情報源を、この判断の型の 2 本目として、この道具・手順に組み込む」の形で書く。調べるだけ・一覧を書くだけの施策は、
  組み込み先が決まっていない限り積まない。
- 完了条件は、組み込んだ道具・手順が新しい情報源から実際に取得した結果（ファイル・件数・更新日）で判定できる形にする。
- 規約上禁止された取得（ログインの迂回・BOT 禁止の明示・有料の壁の回避）を前提にした施策は積まない。
- user のアカウント作成・課金・ログインが要る情報源は積まない（候補として報告にだけ書く）。
