# {{プロジェクト名}} TODO — 無人セッションで 1 SP ずつ消化する作業

目的: {{目的}}

## 運用（人が読む部分）

- **1 ストーリー = 1 回の無人セッション。** runner は Skill `todo-loop`（状態・ログは `.local/todo-loop/`）。
- **積む側**: 実行できるストーリーが無くなると、runner が lens-next（観点 `TODO-lens.md`）の上位 3 件を 1 SP ずつに分解して末尾に積む。
- **調査 = fable、実装 = opus**。見出しの 4 列目がモデル。
- **状態**: `todo`（未着手）/ `doing`（引き継ぎ付きで続行中）/ `done` / `blocked`（人の判断待ち。理由は 引き継ぎ 欄）/
  `awaiting-approval`（外部に出る操作の直前で停止。操作は 外部作用 欄）/ `approved`（人が承認済み。次の回で外部作用まで行う）/ `needs-user`（人にしかできない操作。runner は飛ばす）。
- **承認のしかた**: `awaiting-approval` の行を読み、外部作用 欄の内容でよければ見出しの状態を `approved` に書き換える。
- **順序**: 上から順。依存 欄の ID のローカル作業が終わっていれば（`done` / `awaiting-approval` / `approved`）着手できる。
- **ストーリーポイント**: 1 SP = 1 セッションで確実に終わる量（触るファイル 1〜2、検証は 1 コマンド、目安 45 分以内）。
  収まらないと分かったセッションは、残りを新しいストーリーとして直後に挿入し、自分の 範囲 をやった分に縮めて終える。
- **積むときは、施策を完了まで 1 SP ずつに分解してから積む**（実行側の分割は見積もり違いへの保険で、積む側の分解の代わりではない）。
- 見出し行の書式は runner が機械的に読む: `## S-NN — <項目> | <調査|実装> | <fable|opus> | <状態>`。列の区切り ` | ` と状態語は変えない。
- 各ストーリーの本文は次の欄を持つ: `- 範囲:` / `- 完了条件:` / `- 依存:` / `- 外部作用:` / `- 証跡:` / `- 引き継ぎ:`。
- 外部に出る操作（push・公開・投稿・常駐登録）は無人セッションには許可していない。必ず `awaiting-approval` で止まる。
