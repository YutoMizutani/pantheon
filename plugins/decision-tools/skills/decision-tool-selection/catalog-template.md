# 道具選択の一覧 — 雛形と仕組み

判断・計算の道具（何を取る・買う・外す・いつ止めるを決めるもの）を作る瞬間に、
「問題の形 → 手法」の一覧を引かせる仕組みの説明と、一覧の雛形。
手順の本体は同じフォルダの `SKILL.md`（プラグイン `decision-tools`）。
一覧の中身（行・出典・部品名・実測値）は環境ごとに作り、プロジェクト root の `.local/decision-catalog.md` に置く（gitignore するローカルの置き場）。

## 有効にする（opt-in）

2 つの入り方がある。どちらも入れなければ何も働かない。

- **プラグイン**: `claude plugin marketplace add <この repo>` → `claude plugin install decision-tools@pantheon`。
  道具を作る場面でスキル `decision-tools:decision-tool-selection` が使われる。一覧が無ければ、スキルがこの雛形から作るかを尋ねる。
- **常時ルール（Pantheon の clone 内）**: `.claude/rules/common/decision-tool-selection.md` は配線済みで、
  `.local/decision-catalog.md` がある環境でだけ効く（`.local/hooks/signals.json` と同じ形）。
  下の「一覧の雛形」を `.local/decision-catalog.md` にコピーし、使う行を一次ソース付きで埋めると有効になる。
  止めるときはそのファイルを消す。`.local/` ごと移植すれば一覧も一緒に移る。

スキルはモデルが呼んだときだけ効き、ルールは条件に当たるたびに読まれる。作る瞬間に確実に効かせたいならルールの方。

## なぜ要るか

モデルは手法の系統を知っていても、作る瞬間に問題の形を問われなければその知識は使われない。
同じ形の問題（予算内の選択など）が、道具ごとに別々の近似（比の順に取る・平均だけ・手置きの係数）で書かれ、
答えが正しかったかを測る物差しも無いまま残る。一覧はモデルの手法を縛る物ではなく、作る瞬間に知識を呼び出すための物。

## 一覧の読み方

- **問題の形**: 道具が決めたいことを、対象の言葉を外して言い直したもの。
- **手法の系統**: その形に合う教科書上の手法。
- **選ぶ条件**: 同じ系統の中で、規模・状態が見えるか・確率が既知か でどれを使うか。
- **判定基準の例**: 「答えが正しかったか」を後から測る物差し。
- **共通部品**: その手法を実装した、環境内の再利用部品の名前（あれば）。
- **一次ソース**: 実取得した URL と、根拠の一文の逐語引用。確度ラベルは
  **確定** ＝ 引用文がそのまま主張を支える、**推測** ＝ 引用から導いた・または一次ソース未取得。

## 一覧の雛形

```markdown
# 道具選択の一覧 — 問題の形 → 手法（一次ソース付き）

## 一覧（概要）

| # | 問題の形 | 手法の系統 | 共通部品 |
|---|---|---|---|
| 1 | <問題の形> | <手法の系統> | <部品名 or なし> |

## 1. <問題の形>

- **問題の形**: <対象の言葉を外した 1〜2 文>（例: <この環境の道具>）
- **手法の系統**: <教科書上の手法>
- **選ぶ条件**:
  - <規模・可観測性・確率の既知性による分岐>
  - <近似を使ってよい条件と、近似のときに並べる比較>
- **判定基準の例**: <後から測る物差し>
- **共通部品**: <名前と置き場>
- **一次ソース**: **確定/推測** <実取得した URL> > "<逐語引用>"

## 見直し日

- 作成: <日付>
- 次回の見直し: <日付、または区切りのタスク>
```

一覧の行の例（どの環境でも出やすい形）: 予算内の選択／前提つきツリーの選択／成功・失敗・破壊の繰り返し／
状態を見て次の手を変える／山札から引く確率／結果から確率を直す／相手や乱数のある逐次判断。

## 見直し日

一覧には作成日と次回の見直し日を書く。見直しでは次の 3 点を見る。

1. 各行の「推測」が実測で「確定」に変わったか。
2. 共通部品の名前が実物と一致しているか。
3. 新しい手法の受け口に溜まったものを行に昇格するか。

見直し日を過ぎた一覧を開いたときは、作業を止めずに完了報告へ 1 行添える。

## 新しい手法の受け口

既存の行に合わない問題・別分野の手法を見つけたら、一覧の末尾に 1 項目ずつ足す。

**足す条件**（全部満たすこと）:
1. 既存の行のどれにも当てはまらない理由を 1 行で書ける（「規模が違うだけ」は行の「選ぶ条件」を直す — 新行にしない）。
2. 一次ソースを 1 本以上実取得し、根拠の一文を逐語で引いている（取得していない URL は書かない）。
3. 判定基準の例を 1 つ以上書ける（測れない手法は載せない）。
4. 使う予定の作業か、使わなかった理由を書く。

**書式**:
```
### R-NN — <問題の形> → <手法の系統>（<追加日>・<追加した作業>）
- 既存の行に合わない理由:
- 選ぶ条件:
- 判定基準の例:
- 共通部品（予定名）:
- 一次ソース: **確定/推測** <URL> > "<逐語引用>"
- 行に昇格する条件:
```
