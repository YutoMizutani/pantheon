# Skill の改訂 — 誤りの起き方から手段を選び、本文を書き換え、効いたかを測る

> 仕組みの全体は `docs/self-improvement-loop.md`「Skill の改訂」。経緯はここに書かない。

<important if="Skill（.claude/skills/・projects/*/.claude/skills/）を使った作業を完了報告しようとしている、またはその作業の中で検査の NG・レビュー役の指摘・user の差し戻しを受けて直した、または Skill・その道具・その係の定義を書き換えようとしている">

**Skill を使った作業は、Skill を直してから閉じる。** その作業で起きた誤り（検査の NG・レビュー役の指摘・user の差し戻し・やり直しの周回）を 1 件ずつ、次の順で処理する。誤りが 0 件なら「Skill の改訂: なし（誤り 0 件）」と 1 行書いて閉じる。

1. **起き方を 1 行で書く**: 誰が（親・どの係・どの道具）、どの瞬間に、何を読んで（または読まずに）その誤りを出したか。書けないなら、直す前に transcript と成果物で確かめる。**そして、その誤りが見つかったのはどの工程か**も書く。見つかった工程が出た工程より後ろなら、その間に作った物（図・本文・PDF）は全部作り直しになっている。
2. **手段を選ぶ**。user に言われた手段や、前回使った手段をそのまま採らない。下の候補を全部、この誤りに効くか・どの瞬間に効くかで比べ、効く中で最も上流のものを選ぶ（複数でもよい）:
   - **検査を前に出す** — 誤りが見つかった工程を、その誤りを判定できる最も早い工程（作る・描く・書くより前）へ移す。判定の材料が早く揃うのに後ろで見つかっていたら、まずこれ
   - **出す側を直す** — 誤りを道具・雛形が出しているなら、道具を直して正しい形しか出ないようにする
   - **検査で止める** — 文字の型・数の照合で誤りと決まるなら、成果物を出す前の検査に足す。機械で直せるなら自動で直す機能も付ける
   - **手順の組み方を変える** — 順番（書く前に設計を固める）・分担（作る係と確かめる係を分ける）・入力（係に渡す材料・手本）が原因なら、手順そのものを組み替える
   - **読む文を書き換える** — 意味を読まないと判定できない誤りだけ。誤りを出した係が**その瞬間に読む文**（係の定義・Skill の該当工程）の該当行を書き換える。その係が読まない場所（memory・別ファイルの一覧・経緯の段落）には書かない
   - **消す・まとめる** — 原因が古い指示・食い違う指示・長すぎて読み落とされる指示なら、足さずに消すかまとめる
3. **本文を書き換える**: 同じ趣旨の行があれば、足さずにその行を書き換える。経緯（日付・user の言葉・回数）は Skill の本文に書かず、プロジェクトの経緯ファイル（例: `projects/<name>/rule-history.md`）に書く。
4. **効いたかを確かめてから「直した」と言う**: 道具・検査は、その誤りが出た実物にかけて止まる・出なくなることを確かめ、今ある成果物全部にかけて正しいものを止めないことも確かめる。**数えるのは最終の成果物（user が見る PDF・ページ）の上で、誤りの形が 0 件になったこと。対象は指摘された 1 つでなく、同じ Skill・同じ道具で作った今ある成果物全部（他のページ・他のガイドを含む）で、直した検査をかけて同じ誤りの形を数える。指摘された成果物はその場で 0 件にする。ほかの成果物（別のキャラ・別のビルドのガイドなど）の作り直しは、プロジェクトに無人で消化する TODO（todo-loop の `TODO.md`）があれば 1 件 1 SP で積んで閉じてよく、報告に残りの件数と積んだ ID を書く（積まずに「残っています」で閉じない）。TODO の無いプロジェクトでは同じターンで直してから数える**。最終の成果物が別の検査で止まって作り直せないなら、その検査を通して作り直すところまでが直す範囲で、「別の作業」として古い版を残したまま閉じない（通せない理由が user の判断を要するときだけ、その 1 点を書いて止まる）。正しい形が出たことだけを数えない。直した値が別のファイルに写されて使われていないか（設定の値が本文の表に文字で写されている等）を先にたどり、写しも全部直す。読む文の書き換えは、同じ入力で係を 1 回動かし直して誤りが消えるかを見る。動かし直せないなら「未確認」と書く。
5. **報告に書く**: 完了報告の末尾に「Skill の改訂」として、誤りごとに〈起き方（出た工程／見つかった工程）→ 選んだ手段 → 直したファイル → 確かめ方と結果〉を 1 行ずつ書く。2 の候補のうち、選んだ手段より上流にあるものを全部挙げ、それぞれ選ばなかった理由を短く書く（挙げられないなら、選んだのが最上流だと書く）。

</important>
