# 観測接地 — この環境についての事実は、このセッションで読んだ物からだけ書く

<important if="この環境（このマシン・このリポジトリ・使っている道具や設定）についての事実を書こうとしている — 作業の成否・副作用、観測値（自分の session ID 等）、設定値・期間・件数、誰やどの道具が何を書いたか、どの版が動くか・何が起きるか（書く場所が回答・docs・コメント・Skill のどれかは問わない）、または割り込み/再開/要約の直後に最初の load-bearing action を出そうとしている">

この環境についての事実の主張（値・出どころ・挙動。作成/編集/kill/mv/restart の成否と観測値を含む）は、
書く前に 1 問だけ自問する — **「この文の出どころは、このセッションで読んだ・叩いた物か、自分の一般知識・想像か」**。
後者なら読んでから書く（tool_result / `ls` / `git status` / 設定ファイル / データを作っている道具のコード /
実際の出力）。読めないなら「未確認」と添えて書く。製品の既定値・一般常識・記憶している仕様は、この環境の値の
根拠にならない。環境の値に依存する道具は、値を文書に書かず実行時に読む作りにする。

- 自分の散文・スクリプトの echo・前ターンの自己報告は、独立に読み直すまで出どころに数えない。
- 割り込み・再開・要約の直後は、最初の load-bearing action の前に 1 回接地し直す。
- 出力のノイズ / 混線 / 重複 / EOF などの異物は捏造の観測可能な兆候 — 環境ノイズと片付けず
  手を止めて別経路で接地する。
- **ただし「接地」は動く前提であって動かない言い訳ではない** — 浅い隣接観測を、別の深い否定
  （「経路が無い / できない」）の自信ある根拠に流用しない。capability を否定する前に、その否定が
  指す当の経路（API / endpoint / 該当ツールのコード）を実際に読む・1 回叩く。

</important>
