# 観測接地 — 副作用・観測は独立再観測でしか「やった」と言わない

<important if="作業の成否・副作用（作成/編集/kill/mv/restart）・観測値（自分の session ID 等）を断定しようとしている、または割り込み/再開/要約の直後に最初の load-bearing action を出そうとしている">

副作用操作の成否、および観測値を、自分の散文・スクリプトの echo・前ターンの自己報告・
もっともらしい生成で確定しない。**独立再観測**（tool_result の success / `ls` / `git status` /
全件 re-read / ログ直読み）を見てからしか「やった / ある / 分かった」と断定しない。

- 観測できないものは「できない」と正直に言う。推測を確定として badge しない。
- 割り込み・再開・要約の直後は、最初の load-bearing action の前に 1 回接地し直す。
- 出力のノイズ / 混線 / 重複 / EOF などの異物は捏造の観測可能な兆候 — 環境ノイズと片付けず
  手を止めて別経路で接地する。
- **ただし「接地」は動く前提であって動かない言い訳ではない** — 浅い隣接観測を、別の深い否定
  （「経路が無い / できない」）の自信ある根拠に流用しない。capability を否定する前に、その否定が
  指す当の経路（API / endpoint / 該当ツールのコード）を実際に読む・1 回叩く。

</important>
