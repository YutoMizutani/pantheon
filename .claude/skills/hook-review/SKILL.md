# hook-review — hook の拒否と空回りを数え、撤去の可否を訊く

hook は止めるたびに、Claude に書き直しか呼び直しをさせる。止めた後に同じ入力で止め続けると、拒否と呼び直しが
文脈を食い、本題の作業と回答の質が落ちる。応答の言葉を止める hook は、語を消せば通る抜け道を作り、狙った行動の
代わりに語だけを消す。どちらも、出力の質の低下が報告されるまで見えない。この Skill はそれを数えて先に見つけ、
直すか消すかを user に訊く。

この Skill は**判定と提案だけ**をする。hook・settings を書き換えるのは、user が承認した提案だけ。

## 1. 表を出す

```
python3 heaven/tools/hook_denial_report.py $ARGUMENTS
```

表はそのまま user に見せる。列の意味:

- **拒否**: その hook が止めた回数。
- **同じ入力の再拒否（空回り）**: ツール名と引数が完全に一致する呼び出しを、同じ hook が 2 回目以降に止めた回数。
  止められた後に同じ入力で呼び直して通るのは正しい使い方なので数えない。
- **空回りのあった会話 / 拒否のあった会話**、**最大連続**（1 つの入力が止められた回数の最大）、**期間**、**例文**。
- **持ち主**: その行を出した、今ある hook。本文の先頭の句で束ねた行（`.py` で終わらない行）は、例文の固定の文言から
  道具が引く。**「見つからない」の行は、撤去済みか文面が変わった hook の数字** — 今の hook の数字として判定に使わず、
  表の下に「処置済み（撤去済みの <名前>）」と 1 行添える。先頭の句が今の hook と同じでも、持ち主とみなさない。

続けて、拒否の有無によらず、登録された hook を全部測る。止めない hook は上の表に出ないが、応答のたびに同時に走る。

```
python3 heaven/tools/hook_facts.py --cost
```

手元で最大の会話記録を読ませて、1 本ずつ最大メモリと秒を出す。この表もそのまま user に見せる。注記のうち
「読まなかった」「異常終了」の行と、未測定の一覧は、その本の数字がまだ無いという意味で、軽いという意味ではない。

## 2. 上位の hook を型で分ける

拒否の上位 5 件と、空回りの率が 10% 以上の hook について、本体（読み込み・docstring・判定の部分）と登録
（`.claude/settings.json`・`.local/settings.local.json`。素の grep は gitignored に盲目なので `rg --no-ignore-vcs` か Read）を読み、
次のどちらかに分ける。

- **命令の失敗を防ぐ型**: 止めなくてもその命令は失敗する（シェルの文法・存在しない道具・上書きの禁止など）。
  拒否は失敗の前倒しで、空回りが少なければ劣化ではない。
- **応答や手順の形を求める型**: 止めなくても命令は成功する。止めているのは、Claude が書いた言葉・答える順・読む順。
  劣化を起こすのはこちらの型。

## 3. 撤去・手直しの基準を当てる

応答や手順の形を求める型の hook を全部並べて、材料を 1 回で集める（手で `git log`・`rg -uu` を叩かない —
repo 全体の `rg -uu` は時間切れになる）:

```
python3 heaven/tools/hook_facts.py <hook> [<hook> ...]
```

出るもの: 本体と層・登録（ファイル:行・event・matcher）・入れた日と最初の発火の記録・件名に fix を含む commit・
docstring の日付つきの行・試験・状態ファイル（実在と件数）・発火の記録の rule_id・効き目の判定（`rule_efficacy_report.py`）・
参照（規範と道具の置き場に絞った `rg -uu -l`）。これを元に、各 hook について次を数字で書く。

1. **空回り**: 空回りの率が 10% 以上、または空回りのあった会話が多いか（手順 1 の表）。
2. **狙った失敗の頻度の前後**: 効き目の判定（下がった／横ばい／上がった／判定不能）。「判定不能」は理由も写す
   （「誕生後 4 週と直近 4 週が重なる」＝新しすぎる、`rule_id` が他の hook と共用、など）。共用の規則名の判定は
   その hook の効き目として読まない。transcript の user の訂正で補えるなら補う。
3. **手直しの回数**: fix の commit と docstring の日付つきの行のうち、**自分の誤作動を直した物**だけを数える
   （範囲を広げた・新設した行は数えない — どれを数えたかを 1 行で書く）。2 回以上なら撤去の候補。
4. **狙った語の消失**（言葉を止める hook だけ）: 止めた語が導入の後の assistant の文から消えていないか。
   消えていれば、hook は行動ではなく語を消している。

判定:

- 2 で狙った失敗が減っていない、または 3 が 2 回以上 → **撤去**を先に出す（もう 1 回直す案より前）。
- 空回りが多いが 2 で効いている → **手直し**（止める条件を狭める・止めた後に通る道を作る・止めずに注意だけにする）。
- 命令の失敗を防ぐ型で空回りが少ない → **残す**（理由を 1 行）。
- 手順 1 の測定で 1 本 100MB 超、または注記に「丸読みの候補」→ 上の判定と別に**手直し**（読み方を流し読みに変える。`.claude/hooks/_transcript.py`）。
  判定する本は型によらない。100MB は流し読みに揃えた後に全本が収まった値（最大 91MB）で、丸読みの本は 1 本 1GB を超えた。

安全の hook（破壊的な操作・秘密・自己改変を止める物）は撤去・緩和の提案の対象にしない。読み方の手直しは止める条件を変えないので、緩和に当たらず対象にする。

数字の判定が、上位の規範（ローカル層の CLAUDE.local.md・incident の記録）の名指しや観測と食い違うとき
（例: 撤去の条件に当たるが、ローカル層の原則がその hook を名指ししている）は、判定を書き換えず、両方を並べて
推奨を 1 つ書く（どちらを上に置いたかと理由を 1 行）。

判定は次の列の表で出す（前に出した表を付け直すときも同じ列）:

| hook | 拒否 | 空回り | 狙った失敗の前後 | 直した回数（数えた物） | 判定 |

## 4. 候補を PROPOSAL で出し、user に可否を訊く

候補ごとに、`.claude/agent-refs/self-reflection/proposal.md` を Read して、その書式の `PROPOSAL:` ブロックを作る。

- 撤去は `kind=remove`。`diff_to_apply` に消す物を全部並べる — `hook_facts.py` の登録・本体・試験・状態ファイル・参照を
  そのまま写し、参照は「消す（本体・試験）」「更新する（memory・TODO・道具）」「残す（incident・審理の記録・`.bak`・`.orig`
  など経緯の記録）」に分ける。symlink（`.claude/hooks/local/` → `.local/hooks/`）があればそれも並べる。`rationale` に 3 の数字と、撤去後に狙った失敗を受け持つ既存の機構を書く。
- 手直しは `kind=hook`。同じフォルダの `hook.md` を Read してから書く。
- hook・settings の変更なので `approval: required`。

出す前に、提案ごとに次を通す。`SUPPRESS` が出た提案は出さず、`proposed-suppressed: <見出し>` の 1 行にする。

```
python3 heaven/tools/proposal_ledger.py check-and-record --source "hook-review" --target "<target_file>" --change "<diff_to_apply の本文>"
```

user には、表の後に**候補ごと 1 行**で可否を訊く（例:「`<hook>` を撤去します（拒否 N・空回り M%・前後で訂正が減っていない・
手直し K 回。撤去後は <既存の機構> が受け持つ）。承認／見送り」）。推奨の順に並べ、決定権を選択肢の一覧で返さない。
承認の語を打たせる定型文は求めない。

## 5. 承認された物だけを、このセッションで適用する

- 適用の前に hook の試験（`python3 -m pytest .claude/hooks/tests -q`）を 1 回走らせて件数を控える。
- 承認された提案は、このセッションの中で `diff_to_apply` のとおりに適用する。settings と hook の書き換えは Edit で出す。
- 撤去の後は、`python3 heaven/tools/hook_facts.py <hook>` が「本体: 見つからない・登録: 0 件」になり、参照が「残す」に
  分けた物だけになっていること、hook の試験が「変更前の件数 − 消した試験の件数」で通ることを確かめて報告する。
- 未承認のままセッションが閉じた提案は却下とする（次のセッションへ持ち越さない）。
- 撤去した hook が出力を下げていた経緯は、`heaven/incidents/` に 1 件として残す（数字・根本原因・対応・検知の仕方）。
